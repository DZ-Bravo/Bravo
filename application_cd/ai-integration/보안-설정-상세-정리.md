# Prometheus 보안 설정 상세 정리

## 1. Kubernetes RBAC (Role-Based Access Control) 설정

### 1.1 ServiceAccount 생성
**목적**: Prometheus가 Kubernetes API에 접근할 때 사용할 서비스 계정

**생성 내용:**
```yaml
apiVersion: v1
kind: ServiceAccount
metadata:
  name: prometheus-scraper
  namespace: bravo-monitoring-ns
```

**보안 특징:**
- 네임스페이스 격리: `bravo-monitoring-ns`에만 존재
- 자동 토큰 생성: Kubernetes가 자동으로 Secret 생성
- 토큰 자동 갱신: 만료 시 자동 갱신 가능

### 1.2 ClusterRole 생성
**목적**: Prometheus가 필요한 Kubernetes 리소스에만 접근하도록 권한 제한

**생성 내용:**
```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRole
metadata:
  name: prometheus-scraper
rules:
- apiGroups: [""]
  resources:
  - nodes
  - nodes/metrics
  - nodes/proxy
  - pods
  verbs:
  - get
  - list
  - watch
```

**보안 특징:**
- **최소 권한 원칙 (Principle of Least Privilege)**: 필요한 리소스만 접근 허용
- **읽기 전용 권한**: `get`, `list`, `watch`만 허용 (수정 불가)
- **클러스터 레벨 권한**: 모든 네임스페이스의 노드와 파드 접근 가능 (모니터링 필요)

**허용된 리소스:**
- `nodes`: 노드 정보 조회
- `nodes/metrics`: 노드 메트릭 조회
- `nodes/proxy`: 노드 프록시를 통한 cAdvisor 메트릭 접근
- `pods`: 파드 정보 조회

**제한된 리소스:**
- `secrets`, `configmaps`: 읽기 불가 (민감 정보 보호)
- `deployments`, `services`: 읽기 불가 (불필요)
- `create`, `update`, `delete`: 모든 리소스에 대해 수정 불가

### 1.3 ClusterRoleBinding 생성
**목적**: ServiceAccount에 ClusterRole 권한 부여

**생성 내용:**
```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRoleBinding
metadata:
  name: prometheus-scraper
subjects:
- kind: ServiceAccount
  name: prometheus-scraper
  namespace: bravo-monitoring-ns
roleRef:
  kind: ClusterRole
  name: prometheus-scraper
  apiGroup: rbac.authorization.k8s.io
```

**보안 특징:**
- 특정 ServiceAccount에만 권한 부여
- 네임스페이스 격리 유지

## 2. 토큰 관리 보안

### 2.1 토큰 생성
**방법**: Kubernetes ServiceAccount 토큰 사용

**생성 명령:**
```bash
kubectl create token prometheus-scraper -n bravo-monitoring-ns --duration=8760h
```

**보안 특징:**
- **JWT (JSON Web Token) 형식**: 표준 인증 토큰
- **유효기간 설정**: 8760시간 (1년) - 필요시 조정 가능
- **자동 만료**: 시간이 지나면 자동으로 무효화
- **재생성 가능**: 만료 시 새 토큰 생성 가능

### 2.2 토큰 저장 보안
**파일 위치**: `/tmp/prometheus-k8s-token` (EC2)

**권한 설정:**
```bash
chmod 600 /tmp/prometheus-k8s-token
```

**보안 특징:**
- **파일 권한 600**: 소유자만 읽기/쓰기 가능 (다른 사용자 접근 불가)
- **임시 디렉토리**: `/tmp` 사용 (재부팅 시 삭제 가능)
- **토큰 노출 방지**: 파일 내용이 로그에 남지 않도록 주의

**권장 사항:**
- 정기적인 토큰 갱신
- 토큰 파일 백업 시 암호화
- 토큰 내용을 로그에 남기지 않기

## 3. 네트워크 보안

### 3.1 Kubernetes API 서버 접근
**방법**: Kubernetes API 서버를 통한 간접 접근

**설정:**
```yaml
- job_name: kubernetes-cadvisor-node1
  scheme: https
  tls_config:
    insecure_skip_verify: true
  static_configs:
    - targets:
        - CD954D03FD7521324954E667CB2450E9.yl4.ap-northeast-2.eks.amazonaws.com:443
  metrics_path: /api/v1/nodes/ip-10-0-17-71.ap-northeast-2.compute.internal/proxy/metrics/cadvisor
  bearer_token_file: /tmp/prometheus-k8s-token
```

**보안 특징:**
- **HTTPS 사용**: 암호화된 통신
- **Bearer Token 인증**: 토큰 기반 인증
- **API 서버 프록시**: 직접 노드 접근 대신 API 서버를 통한 접근
- **인증 필요**: 모든 요청에 토큰 필요

**주의사항:**
- `insecure_skip_verify: true`: 내부 네트워크에서만 사용 (프로덕션에서는 인증서 검증 권장)

### 3.2 노드 직접 접근 방지
**원래 방법 (사용 안 함)**:
- 노드 IP:포트로 직접 접근 (10.0.17.71:10250)
- 보안 위험: 노드에 직접 접근

**현재 방법 (사용 중)**:
- Kubernetes API 서버를 통한 접근
- 보안 장점: API 서버의 인증/인가 메커니즘 활용

**토큰 파일**:
- 위치: `/tmp/prometheus-k8s-token`
- 권한: `600` (소유자만 읽기/쓰기)

### 4.2 파일 내용 보호
**토큰 파일**:
- 평문 저장 (JWT 토큰 자체가 암호화된 형식)
- 파일 시스템 권한으로 보호
- 로그에 남기지 않기

**설정 파일**:
- 토큰 경로만 저장 (실제 토큰 내용은 별도 파일)
- 설정 파일 유출 시에도 토큰은 안전

## 6. 보안 모범 사례 적용

### 6.1 적용된 사례
✅ **최소 권한 원칙**: 필요한 리소스만 접근 허용
✅ **네임스페이스 격리**: 리소스 분리
✅ **토큰 기반 인증**: 강력한 인증 메커니즘
✅ **HTTPS 통신**: 암호화된 통신
✅ **파일 권한 제한**: 민감 정보 보호
✅ **읽기 전용 권한**: 수정 불가능

### 6.2 개선 가능한 사항
⚠️ **인증서 검증**: `insecure_skip_verify: true` → 인증서 검증 활성화 권장
⚠️ **토큰 만료 시간**: 1년 → 더 짧은 기간 권장 (예: 30일)
⚠️ **토큰 암호화 저장**: 파일 시스템 암호화 또는 Secrets Manager 사용
⚠️ **감사 로깅**: Prometheus 접근 로그 모니터링
⚠️ **정기적 토큰 갱신**: 자동 갱신 스크립트 구현
